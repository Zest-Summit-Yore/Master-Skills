# 律师三层代理编排

本技能只负责模型路由、任务依赖和验收。主线程负责理解用户目标、确定边界、组织委派和整合交付；不得根据自我识别猜测主线程模型，也不得要求用户先切换主模型。

## 1. 模型组合与启用条件

实际委派前检查 `spawn_agent` 的当前 schema，并只使用已声明支持的字段：

| 层级 | 参数 | 主要职责 |
| --- | --- | --- |
| Astra Low | `model = "gpt-6-astra"`，`reasoning_effort = "low"` | 复杂法律框架、跨文件或跨来源冲突、重大性排序、高风险结论、最终实质复核 |
| Sol Medium | `model = "gpt-5.6-sol"`，`reasoning_effort = "medium"` | 边界明确的合同审阅、法律分析、风险说明、条款及正式中文文字起草 |
| Luna Max | `model = "gpt-5.6-luna"`，`reasoning_effort = "max"` | 文件盘点、读取、OCR、客观提取、表格整理、文件制作编辑、渲染和技术验证 |

若 schema 支持 `fork_turns`，每次传入 `fork_turns = "none"`；若只支持 `fork_context`，传入 `fork_context = false`。子代理 prompt 是唯一任务背景，不依赖继承的主线程历史。

只检查当前任务实际需要的模型：

- 涉及附件、VDR、图片、扫描件、Word、PDF、Excel 或批量文件时，Luna Max 是文件处理必需角色。
- 涉及法律效果、风险、审阅意见、事实评价或专业文字时，至少使用 Sol Medium 或 Astra Low。
- 涉及全局分析框架、相互矛盾的材料、控制文件优先级、重大问题排序、敏感结论或高风险最终文本时，使用 Astra Low。
- 边界明确、事实前提和审阅立场已经确定的独立法律问题，优先使用 Sol Medium；需要更高层复核时，采用 Sol 起草、Astra 复核。

某个必需组合不可用时，暂停依赖该角色的工作并准确说明缺少的模型或 reasoning；不得静默降级。与该角色无依赖且不会造成错误前置的工作可以继续。只有文件操作而无实质分析时不强制启用 Sol 或 Astra；只有文字型法律问题且没有文件操作时，不必启用 Luna。

任务名应与实际参数一致，使用 `_astra_low`、`_sol_medium` 或 `_luna_max` 结尾，例如 `major_issues_astra_low`、`loan_review_sol_medium`、`ocr_bundle_luna_max`。

## 2. 法律工作的职责边界

### Luna Max：材料与文件执行层

将以下工作交给 Luna：

- 盘点目录、VDR 和附件，识别文件类型、版本、日期、当事方和缺失材料。
- 读取 DOCX、PDF、图片和表格；对扫描件执行 OCR；保留页码、条款号、单元格和文件路径等定位信息。
- 提取定义、金额、比例、日期、交叉引用、签署页、修订痕迹、批注、表格和元数据。
- 对多个版本作客观差异比对，建立原文摘录表、来源索引、问题底稿和数字核对表。
- 按 Sol 或 Astra 已批准的最终文字创建或编辑 Word、PDF、Excel 等文件，实施 Track Changes、自动编号、样式、目录、页眉页脚和交叉引用。
- 输出文件并进行技术验收，包括 ZIP/OOXML 完整性、修订保留、页码、编号连续性、缩进、分页、跨页表格、字体替换和逐页渲染检查。

Luna 不得：

- 判断违法性、法律适用、条款是否可接受、风险等级、控制文件效力或谈判立场。
- 独立起草或改写法律结论、审阅意见、Major Issue、Request List、合同权利义务或限定性措辞。
- 根据文件名、关键词、单一材料或 OCR 结果推断事实；不得把 OCR 文本视为无误原文。
- 为了改善文风而改变已经批准文字的法律效果、范围、例外、条件、责任或不确定性表述。

若客观整理需要隐含法律分类，例如“受制裁主体”“资金占用”“关联方”“重大违约”或“受控物项”，Luna 只能提取相关事实并提交 Sol 或 Astra 判断。

### Sol Medium：封装的法律分析与写作层

将以下工作交给 Sol：

- 在法域、基准日期、审阅立场、事实前提和交付标准明确时，审阅单份合同、某组条款或一个独立法律问题。
- 分析定义、权利义务、先决条件、承诺、违约、担保联动、冲突条款，以及无需裁决控制文件的局部跨文件不一致及其法律后果。
- 起草或优化合同条款、文字版审阅意见、律师问题、Request List、访谈问题、风险说明和法律备忘录的独立章节。
- 对公开法律来源和原始材料进行规则适用分析，明确事实依据、适用规则、推理、结论、限制条件和待核实事项。
- 按用户立场形成专业、简洁、可直接使用的中文文字，并区分纯措辞问题和实质法律风险。

Sol 不得自行补足缺失事实、扩大法域或交易范围，也不得把管理层陈述、公开报道、投诉、指控或代理推断提升为已核实事实。遇到材料冲突、全文缺失、控制文件不明或重大性需要跨事项权衡时，应提交 Astra 或主线程处理。

### Astra Low：复杂判断与复核层

将以下工作交给 Astra：

- 设计复杂尽调、交易文件包或合规事项的分析框架，确定问题之间的依赖和重大性标准。
- 解决跨协议、跨版本、跨法域、跨来源或事实与法律之间的冲突。
- 分析交易结构、主体角色、真实业务链条、控制文件优先级以及重大法律和商业后果。
- 对高风险结论、Major Issue 排序、谈判策略、正式对外意见和 Sol 的复杂草稿作实质复核。
- 在证据不完整或存在多种合理解释时，决定应作何种限定、提出哪些补充问题，以及哪些结论暂不能形成。

Astra 的输出仍须引用可回溯的材料和现行法律来源。主线程负责比较 Astra、Sol 与 Luna 的产物并作最终整合，不得仅凭子代理声明“已完成”即接受结果。

## 3. 文件型法律任务的默认顺序

1. 主线程明确目标、用户立场、法域、基准日期、材料范围、输出形式、事实状态和验收标准。
2. Luna 读取全部相关材料，形成带来源定位的证据底稿，并向 Sol 或 Astra 提供相关文件的完整提取正文以及必要附件、定义和交叉引用上下文；不得仅用摘要或关键词摘录替代全文。提取不完整时，列明 OCR 不确定项、缺页、打不开的文件、版本关系、未核实信息及其影响。
3. Sol 分析边界明确的独立问题并起草；Astra 处理全局框架、重大风险和冲突，必要时复核 Sol 草稿。
4. 主线程组织、汇总并确认交付版本。整合中如需新增或改写法律判断、正式法律文字或限定语，交由 Sol 或 Astra 完成；复杂跨事项判断交由 Astra。凡涉及权利义务、风险定性、限定语或法律结论，不得由 Luna 自行补写。
5. 用户要求文件交付时，Luna 将批准文字写入模板或原文件，保留要求的格式和修订方式，并完成输出与渲染验证。
6. Sol 或 Astra 检查最终文件中的全部新增或修改的权利义务、法律结论和限定语，并按风险抽查其他内容；Luna 复核版式与技术完整性，主线程交付。

没有文件输入或输出时，跳过 Luna 阶段。用户只要求文字版意见时，不得擅自创建或修改 Word。用户要求修改原文件时，先保留源文件并明确修订方式，不得覆盖未经授权的内容。

## 4. 证据和表述规则

所有角色必须区分并保留以下来源状态：文件原文、管理层陈述、公开信息、投诉或指控、代理推断、已核实事实；同时单独标注 OCR 等提取方式。来源状态和提取方式可以并列，不能强制单选。关键结论应能回溯至具体文件、页码、条款、单元格或权威网页；OCR 关键文字须与页面图像复核。

法律、监管清单、控制目录、许可要求和公开主体信息具有时效性时，应按任务基准日期实时核验。不得仅凭产品名称、CAS、HS 编码、新闻报道或名称相似性形成受控、违法或列名结论。

Request List 和律师问题应合并重复事项，保留必要问题，采用书面化、法律化、可直接发送的表达。敏感安排使用中性求证措辞，例如“代为承接、开展或履行”、代收代付、主体不一致和四流一致；不得把调查方向写成事实认定。

## 5. 委派契约与并行控制

每个子代理 prompt 至少写明：单一目标；用户及审阅立场；法域和基准日期；输入文件及来源状态；允许读写范围；禁止推断和不得改变的内容；交付格式；完成条件；验证方式；回报中应列出的来源、风险和未解问题。

文件提取与依赖其内容的法律分析应串行。互不依赖的文件可分别由 Luna 处理，边界独立的法律问题可分别由 Sol 处理；复杂跨事项判断由 Astra 完成，主线程只组织、汇总并确认交付版本。共享目录中的写入任务必须分配互斥文件，或按“锁定文字—制作文件—复核”的顺序串行，避免多个代理同时修改同一文档。

## 6. 典型路由

| 场景 | 路由 |
| --- | --- |
| 并购尽调及 Request List | Luna 盘点和提取 → Sol 分析缺口并起草必要问题 → Astra 处理重大性和敏感表述 → Luna 按批准内容制作清单文件 |
| 贷款或融资文件审阅 | Luna 读取全文和相关担保文件、整理定义与差异 → Sol 从指定立场形成审阅意见 → Astra 处理重大风险或跨文件冲突 |
| 多份交易文件一致性核对 | Luna 建立当事方、金额、日期、比例和条款对照 → Sol 分析法律后果和修订建议 → Astra 决定控制文件、优先级和重大问题 |
| 出口管制或生产合规 | Luna 收集产品资料、许可和权威来源 → Sol 分析规则适用和证据缺口 → Astra 处理交易链条、分类不确定性和最终结论 |
| Word Track Changes 或正式报告 | Sol/Astra 先定稿法律文字 → Luna 应用修订、格式化、输出和逐页渲染 → Sol/Astra 抽查法律效果 |

最终回复应简要说明实际使用的 Astra Low、Sol Medium、Luna Max 分工，已完成的实质与技术验证，以及仍受材料、来源或工具条件限制的事项。
